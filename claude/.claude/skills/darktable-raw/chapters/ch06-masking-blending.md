# Chapter 6: Masking & Blending

## Core Idea
Every module can optionally **blend** its output with its input via a blend mode + opacity, and that opacity can be made spatially local via a **mask** — drawn, parametric, drawn+parametric, or raster. This is how edits are confined to part of an image (the window, the dress, the skin) without affecting the rest.

## Frameworks Introduced

- **Blending**: reprocess module output with input using a *blend operator* + *opacity* (0% = no effect, 100% = full). Global opacity slider applies uniformly; a mask makes opacity vary per pixel.

- **Mask types** (icons at the bottom of each module, left→right):
  - **off**: no blending.
  - **uniformly**: blend mode + single opacity slider, whole image.
  - **drawn mask**: opacity from drawn shapes (circle, ellipse, path, brush, gradient).
  - **parametric mask**: opacity from pixel *properties* (value in a chosen channel) — e.g. "only affect pixels brighter than X."
  - **drawn & parametric**: combination (e.g. draw a region, then restrict by tone within it).
  - **raster mask**: reuse a mask generated by an *earlier* module in the pipeline (can be inverted) — the basis for two-instance mixed-light correction.

- **Blending options**: choose the **mask color space**; choose whether the parametric mask reads the module's *input* (default) or *output* channels.

## Key Concepts
- **Drawn shapes**: circle, ellipse, path, brush (pressure-variable), gradient. Each has feather/falloff.
- **Parametric mask channels**: build opacity from L/C/h, RGB, etc. — sliders define a fuzzy in/out range.
- **Raster mask reuse**: the canonical pattern for applying the *same* selection to multiple modules or instances.
- **Multiple instances**: any module can have several instances, each with its own mask — e.g. color calibration global + masked, or local contrast at two scales.
- **Mask manager** & **display mask** (toggle): always visualize the mask while tuning.

## Anti-patterns
- **Parametric mask reading the wrong channel space**: opacity won't track what you expect — set the blending color space deliberately.
- **Hard mask edges**: feather drawn shapes / soften parametric ranges to avoid visible transitions.
- **Forgetting masks are per-instance**: a mask lives on the instance that owns it; reuse via raster mask, don't redraw.

## Reference Tables

| Goal | Mask approach |
|---|---|
| Affect a drawn region (window, face) | drawn mask (shape + feather) |
| Affect by tone (only highlights/shadows) | parametric mask |
| Affect a toned region within an area | drawn & parametric |
| Reuse one selection across modules/instances | raster mask (optionally inverted) |
| Mixed light sources | 2× color calibration + inverted raster mask (Ch 3) |

## Worked Example — pull down only the window in the communion frame
1. On `tone equalizer` (or an exposure instance), enable **drawn mask** → gradient or path over the bright window/garden.
2. Feather the edge so the recovery blends into the conservatory frame.
3. Optionally add a **parametric** restriction on luminance so only the brightest pixels inside the drawn region are affected — the foliage edges stay untouched.
4. Toggle display-mask to confirm the selection hugs the window, then dial the exposure pull.

## Key Takeaways
1. Blending = output⊕input via blend mode + opacity; masks make opacity local.
2. Four mask families: drawn (location), parametric (pixel value), combined, raster (reuse an earlier mask).
3. Raster masks + multiple instances enable mixed-light WB and multi-scale local contrast.
4. Always set the blending color space deliberately and visualize the mask while tuning.
