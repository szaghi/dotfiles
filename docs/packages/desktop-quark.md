# quark desktop

The `desktop/` package is the Wayland desktop of quark, a Chuwi Minibook X N150 running CachyOS: **sway** as
compositor, **Noctalia** as desktop shell (bar, launcher, notifications, OSDs, lock screen), **foot** as terminal,
Qt and GTK themed from one palette. It is machine-specific: `machines/quark` lists it, so adam and astrobit never
stow it. The package tracks only authored files. Noctalia generates the rest, and that split shapes the whole
layout.

## Install

```bash
bash ~/dotfiles/dotify.sh desktop     # symlink the configs
~/.scripts/quark-desktop-install      # root-owned parts: touchpad hwdb, WiFi power save
```

Then enable the Noctalia templates in the GUI (see [Templates](#templates-are-gui-only)) and run `noctalia-retheme`.

## Files

| Source | Deployed to | Sets |
|---|---|---|
| `desktop/.config/sway/config` | `~/.config/sway/config` | Compositor: key bindings, output scale, inputs, Noctalia startup |
| `desktop/.config/foot/foot.ini` | `~/.config/foot/foot.ini` | Terminal font; colours included from the generated theme |
| `desktop/.config/qt6ct/qt6ct.conf` | `~/.config/qt6ct/qt6ct.conf` | Qt6: Fusion style, custom palette from Noctalia |
| `desktop/.config/chrome-flags.conf` | `~/.config/chrome-flags.conf` | Chrome: native Wayland, GTK4 |
| `desktop/.config/noctalia/patches/README.md` | `~/.config/noctalia/patches/README.md` | Rationale for the local patches (documentation only) |
| `desktop/system/` | not stowed | Root-owned files, installed by `quark-desktop-install` |

No Noctalia `settings.toml` is tracked. The helper scripts `noctalia-retheme` and `noctalia-qt-dim-disabled` live in
the [scripts](/packages/scripts) package (`scripts/.scripts/`, deployed to `~/.scripts/`).

## sway

`$mod` is `Mod4` (Super). Directions are vim keys: `$left h`, `$down j`, `$up k`, `$right l`. `$term` is `foot`.

### Outputs and layout

- `output DSI-1 scale 1.5`: the internal 1200x1920 panel.
- `output * bg /usr/share/backgrounds/sway/Sway_Wallpaper_Blue_1920x1080.png fill`.
- `workspace_layout tabbed`: new workspaces open tabbed.
- `for_window [app_id="nmtui"] floating enable, resize set 700 500`.
- No idle or lock daemon is configured in sway; the lock screen is Noctalia's.

### Inputs

| Device | Settings |
|---|---|
| `type:touchpad` | `tap`, `natural_scroll`, `dwt` enabled; `pointer_accel 0.1`; `accel_profile flat` |
| `type:keyboard` | `xkb_layout "usit"`; `xkb_options "caps:escape,lv3:ralt_switch"` (Caps Lock is Escape, right Alt is AltGr) |

The touchpad uses the `flat` profile because this SIPODEV pad reports no pressure or touch-major: libinput cannot tell
a resting finger's creep from deliberate motion, and `adaptive` amplified the creep into drift. The second half of the
fix is the hwdb fuzz in [desktop/system](#desktop-system).

### Startup

| Line | Effect |
|---|---|
| `exec_always ... systemctl --user set-environment QT_QPA_PLATFORMTHEME=qt6ct && dbus-update-activation-environment --systemd QT_QPA_PLATFORMTHEME` | Qt reads qt6ct; without the variable Qt ignores qt6ct |
| `exec noctalia --daemon` | Starts the shell. It replaced waybar; the `bar { swaybar_command waybar }` block is kept commented out |
| `include /etc/sway/config.d/*` | Distribution snippets |
| `include ~/.config/sway/noctalia` | Generated by Noctalia: palette colours for sway |

## foot, Qt, GTK, Chrome

**foot.** `font=MesloLGS Nerd Font:size=14`; foot's default `monospace:size=8` is unreadable on the 1200x1920 panel
at scale 1.5, and the Nerd Font variant renders powerline separators and icons. Colours come from
`include=~/.config/foot/themes/noctalia`, a generated file.

**Qt.** `qt6ct.conf` sets `style=Fusion`, `custom_palette=true` and `color_scheme_path` to the generated
`~/.config/qt6ct/colors/noctalia.conf`. Fusion is required: the other Qt styles ignore custom palettes. `qt5ct` is
deliberately not installed; there is no `qt5-base` on quark.

**GTK.** No GTK file is authored. Noctalia writes `gtk-3.0/noctalia.css` and `gtk-4.0/noctalia.css`; the GTK theme
is `adw-gtk3-dark`.

**Chrome.** `chrome-flags.conf` holds `--ozone-platform-hint=auto` (native Wayland, sharper on the 1.5x output) and
`--gtk-version=4` (frame, menus and toolbar follow `adw-gtk3-dark`). Arch's `/usr/sbin/google-chrome-stable`
wrapper reads `$XDG_CONFIG_HOME/chrome-flags.conf`, not `google-chrome-flags.conf` (the Chromium name, silently
ignored). One GUI step is also needed once: `chrome://settings/appearance`, Theme = GTK, Mode = Dark. Check with
`chrome://version`: the command line lists both flags and the Ozone platform is `wayland`.

## Authored vs generated

Noctalia renders the active palette into config files of other applications through **templates**. Those files are
regenerated on every palette change and are gitignored:

```
~/.config/sway/noctalia              ~/.config/gtk-3.0/noctalia.css
~/.config/foot/themes/               ~/.config/gtk-4.0/noctalia.css
~/.config/alacritty/themes/          ~/.config/qt6ct/colors/
~/.config/btop/themes/               ~/.config/starship.toml
```

Tracking them would put palette churn in git. Worse, stow folds a package directory into a single directory
symlink when it can: `~/.config/foot` would then point into the repo, and Noctalia would write its output straight
into `desktop/`. The package therefore holds individual files (`.config/sway/config`, not `.config/sway/`), stow
links file by file, and the generated siblings stay outside the repo as real files.

::: warning
Never add to `desktop/` a directory whose sibling files Noctalia writes.
:::

## Templates are GUI-only

The enabled-template set has no supported `settings.toml` representation: a hand-written `[templates]` section is
rejected by `noctalia config validate`. Enable it once, by hand, in Noctalia's settings, Templates:

```
gtk3, gtk4, qt, foot, alacritty, btop, sway
```

`quark-desktop-install` prints this reminder; it cannot provision the set.

## noctalia-retheme

```bash
noctalia-retheme --list                 # available schemes + current
noctalia-retheme builtin Nord           # switch to a builtin scheme
noctalia-retheme community Solarized    # switch to a cached community palette
noctalia-retheme                        # re-apply the current palette + patch
```

Builtins: Catppuccin, Dracula, Gruvbox, Kanagawa, Nord, Oxocarbon. Community palettes are the JSON files cached in
`~/.local/state/noctalia/community-palettes/`. The script switches the scheme, applies the templates, waits for the
files to settle, then runs `noctalia-qt-dim-disabled`. Afterwards: open a new foot or alacritty window, restart
GTK and Qt applications, `swaymsg reload` for sway borders. btop is signalled by its own hook.

It works around two daemon behaviours:

1. **`color-scheme-set` does not reload the daemon.** It persists the choice to `settings.toml`, and
   `color-scheme-get` reports the new scheme at once, but templates keep rendering from the previously loaded
   palette. Without the `noctalia msg config-reload` the wrapper issues, foot and btop update while sway, GTK and Qt
   keep the old colours.
2. **`templates-apply` returns `ok` before writing.** Rendering is asynchronous, and `~/.config/sway/noctalia` is
   written last, seconds after the rest. The wrapper polls the checksums of the generated files (qt6ct, foot, sway,
   btop, gtk-3.0) until they stop changing for about 1.5 s, up to about 12 s. It hashes content rather than reading
   mtime, because Noctalia skips rewriting a file whose content is unchanged.

## noctalia-qt-dim-disabled

Noctalia's Qt template emits `disabled_colors` byte-identical to `active_colors`, so disabled Qt widgets look
enabled. `noctalia-qt-dim-disabled` rewrites the `disabled_colors` row of `~/.config/qt6ct/colors/noctalia.conf`:
it blends the foreground roles toward the `window` background by the `FADE` factors at the top of the script, and
gives the disabled `highlight` the `alternateBase` colour. Background roles are untouched, so disabled controls stay
on the same surface. Values are computed from the active palette, so it works for any scheme. It is idempotent
("already dimmed; nothing to do").

Noctalia reverts the patch on a colour-scheme change, on `templates-apply` and on a dark/light switch. Noctalia's
hooks expose only a `wallpaper_changed` event, so nothing triggers the patch automatically: use `noctalia-retheme`,
or run the patch by hand. Measured on Solarized dark: active text 4.75:1, disabled text 2.76:1, disabled
placeholder 2.21:1.

## Editors and the ANSI palette

Every Noctalia palette lifts ANSI 8 (bright black) above the background, so dim terminal text stays legible. A
16-colour editor colorscheme that paints `Normal` from ANSI 8 becomes unreadable: the old
`altercation/vim-colors-solarized` gave body text 2.25:1 and comments 1.32:1. The fix sits in the editors, not in
the terminal: vim uses `vim-solarized8` with `termguicolors`, nvim `solarized.nvim` in 24-bit, and neither reads
the ANSI palette. See [vim](/packages/vim) and [nvim](/packages/nvim).

::: warning
Do not reintroduce a `bright0` patch for foot. It was removed because any template render outside
`noctalia-retheme` silently reverted it.
:::

## desktop/system

`desktop/system/` is not a stow path: `desktop/.stow-local-ignore` excludes `^/system$`. Its paths mirror `/`, and
`~/.scripts/quark-desktop-install` copies them with `sudo`.

| Source | Installed to | Sets |
|---|---|---|
| `system/udev/hwdb.d/61-evdev-local.hwdb` | `/etc/udev/hwdb.d/` | `fuzz=8` on axes 00, 01, 35, 36 of the SIPODEV/Hantick `0911:5288` touchpad |
| `system/modprobe.d/iwlwifi-no-powersave.conf` | `/etc/modprobe.d/` | `options iwlmvm power_scheme=1` (active, instead of the default 2, balanced) |
| `system/NetworkManager/conf.d/wifi-powersave-off.conf` | `/etc/NetworkManager/conf.d/` | `wifi.powersave = 2` (disable) |

What the script does, in order:

1. **Touchpad hwdb.** Upstream `60-evdev.hwdb` sets fuzz only on `ABS_X`/`ABS_Y`; libinput reads motion from the
   multitouch axes `ABS_MT_POSITION_X/Y` (35/36 hex), which upstream leaves at 0, so the pointer drifts under a
   resting finger. The script installs the entry, runs `systemd-hwdb update`, then `udevadm trigger` on the touchpad
   event device: libinput reads fuzz only at device init, so `swaymsg reload` does not apply it.
2. **WiFi power save.** Client-side power save hurts the Moonlight stream from astrobit. quark's card is Intel:
   `iwlwifi.power_save` is already off, the knob is `iwlmvm.power_scheme`. The module parameter applies on the next
   boot. The `conf.d` default reaches only profiles with no explicit preference, so the script also sets
   `802-11-wireless.powersave 2` on the active wireless profile and brings it up again; an ssh session over that
   link can drop.
3. **Verification.** Counts the `LIBINPUT_FUZZ` properties on the touchpad and expects 4.
4. **Reminder** of the GUI-only template set.

It is idempotent and exits 1 if a step failed.

## Things to know

- The hwdb match ends in `Touchpad:*`, not upstream's `Touchpad:dmi:`. With an identical pattern hwdb merges the two
  entries and upstream's properties win.
- Do not add `d0i3_disable` to the iwlwifi options: it does not exist in this kernel.
- `nmcli device reapply` reapplies IP settings, not radio ones. The profile must carry `powersave=2` itself.
- **Chrome is not themeable.** Noctalia has no Chrome template and cannot gain one: Firefox theming works only
  through Pywalfox's extension and native host, and Chrome's tab strip, toolbar and omnibox accept only a Web Store
  theme or Chrome's own settings. Chrome will not be Solarized. Revert the flags with
  `rm ~/.config/chrome-flags.conf` and a Chrome restart.
- The patch rationale and measurements live in `desktop/.config/noctalia/patches/README.md`.
